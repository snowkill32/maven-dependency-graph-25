# Граф зависимостей Maven - вариант 25

Практическая работа №2 по конфигурационному управлению.
Реализован **этап 1: минимальный прототип с конфигурацией**
по заданию «УНБО-04-25», стр. 80.

Приложение принимает настройки через опции командной строки,
проверяет их и выводит все четыре значения в формате `ключ=значение`.
Язык реализации - Python; используется только стандартная библиотека.
Менеджеры пакетов и сторонние библиотеки для получения зависимостей
не используются.

## Требования и запуск

Нужен Python 3.10 или новее. Устанавливать библиотеки и собирать проект
не требуется. Все команды ниже выполняются из корня репозитория.

```shell
python --version
python -m src --help
python -m src --package org.example:demo:1.0 --repository https://repo.maven.apache.org/maven2/
```

Результат последней команды:

```text
package=org.example:demo:1.0
repository=https://repo.maven.apache.org/maven2/
test_mode=false
ascii_tree=false
```

Скрипты запуска принимают те же опции и сохраняют код завершения программы:

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode --ascii-tree
```

```shell
sh run.sh --package A --repository examples/repository.json --test-mode --ascii-tree
```

Скрипты сами переходят в каталог проекта. При прямом запуске `python -m src`
относительный путь к файлу считается от текущего рабочего каталога.
Пути с пробелами нужно заключать в кавычки.

## Настройки

| Опция | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package` | Координаты Maven или имя тестового пакета | Обязательна |
| `--repository` | Базовый URL или путь к тестовому файлу | Обязательна |
| `--test-mode` | Выбрать локальный тестовый репозиторий | `false` |
| `--ascii-tree` | Включить настройку вывода ASCII-дерева | `false` |
| `-h`, `--help` | Показать справку и завершить программу | - |

В обычном режиме пакет задается как `groupId:artifactId:version`:
например, `org.example:demo:1.0` или `org.example:my-lib:1.0-SNAPSHOT`.
Все три части обязательны, пробелы недопустимы. Идентификатор группы
состоит из букв, цифр, `_` и разделяющих сегменты точек.
В идентификаторе артефакта дополнительно допускаются `.` и `-`,
в версии - `.`, `_`, `+` и `-`.

Для репозитория требуется абсолютный HTTP(S) URL с именем сервера
и, при необходимости, портом от 1 до 65535. Пробелы, логин и пароль,
параметры запроса и фрагмент не допускаются. Проверяется синтаксис;
доступность сервера на первом этапе не проверяется.

С `--test-mode` имя пакета - одна большая латинская буква от A до Z,
а репозиторий - существующий доступный для чтения файл UTF-8.
Пример файла находится в `examples/repository.json`.
На первом этапе содержимое читается только для проверки доступности
и кодировки; структура графа и наличие пакета в файле не проверяются.

`--test-mode` и `--ascii-tree` являются флагами: присутствие включает
настройку, отсутствие выключает. Запись `--ascii-tree=true` ошибочна.

На этапе 1 флаг `--ascii-tree` сохраняется и выводится в конфигурации.
Загрузка зависимостей относится к этапу 2, построение графа - к этапу 3,
порядок загрузки - к этапу 4, визуализация и ASCII-дерево - к этапу 5.

## Пример тестового режима

```shell
python -m src --package A --repository examples/repository.json --test-mode --ascii-tree
```

```text
package=A
repository=examples/repository.json
test_mode=true
ascii_tree=true
```

Пример тестового файла описывает будущий граф `A -> B, C` и `B -> D`.
Выбран формат JSON: ключ - пакет, значение - список прямых зависимостей.
Сам граф на первом этапе не обходится.

## Демонстрация обработки ошибок

Все приведенные ошибочные команды завершаются с кодом `2`,
показывают подсказку `usage` и сообщение `error` в stderr.
Успешный запуск и справка завершаются с кодом `0`.
При ошибке конфигурация не выводится и Python traceback отсутствует.

Неверный пакет:

```shell
python -m src --package demo --repository https://example.org
```

Сообщение: `--package: ожидается groupId:artifactId:version` с примером.

Неверный репозиторий в обычном режиме:

```shell
python -m src --package org.example:demo:1.0 --repository not-a-url
```

Сообщение: `--repository: нужен абсолютный HTTP(S) URL с именем сервера`.

Неверное значение флага тестового режима:

```shell
python -m src --package A --repository examples/repository.json --test-mode=true
```

Сообщение: `argument --test-mode: ignored explicit argument 'true'`.

Неверное значение флага ASCII-дерева:

```shell
python -m src --package org.example:demo:1.0 --repository https://example.org --ascii-tree=true
```

Сообщение: `argument --ascii-tree: ignored explicit argument 'true'`.

Несуществующий файл в тестовом режиме:

```shell
python -m src --package A --repository missing.json --test-mode
```

Сообщение: `--repository: тестовый файл не найден или путь ведет к каталогу`.

Также обрабатываются отсутствие обязательных опций и их значений,
пустые строки, неверное имя тестового пакета, каталог вместо файла,
ошибка чтения, неподходящая кодировка, неверные порты и схемы URL,
неизвестные опции и попытки сокращать их имена.

## Тесты

```shell
python -m unittest discover -s tests -v
```

20 тестов, включая группы проверок разных ошибочных значений.
Тесты проверяют конфигурацию, сообщения ошибок и коды завершения.
Два интеграционных теста запускают CLI отдельным процессом.
Доступ к сети не нужен, временные тестовые файлы удаляются автоматически.
Отказ в доступе к файлу моделируется через `unittest.mock`,
чтобы тест одинаково работал в Windows и Linux.

## Структура и функции

```text
src/
  __init__.py       описание пакета приложения
  __main__.py       точка входа python -m src
  cli.py            разбор опций и вывод
  config.py         модель конфигурации и проверки
tests/
  test_cli.py       проверки всех четырех параметров
  test_launch.py    запуск CLI отдельным процессом
examples/
  repository.json  тестовый репозиторий
run.bat            запуск в Windows
run.sh             запуск в Linux/macOS
```

| Функция или класс | Назначение |
| --- | --- |
| `Config` | Неизменяемая модель четырех настроек |
| `build_parser()` | Описывает обязательные опции, флаги и справку |
| `parse_config(argv)` | Получает аргументы, создает и проверяет `Config` |
| `format_config(config)` | Формирует четыре строки `ключ=значение` |
| `main(argv)` | Запускает проверку, печатает настройки, возвращает `0` |
| `validate_config(config)` | Выбирает правила для обычного или тестового режима |
| `validate_package(package, test_mode)` | Проверяет координаты Maven или букву A-Z |
| `validate_url(repository)` | Разбирает URL и добавляет имя опции к ошибке |
| `_validate_url_parts(url)` | Проверяет схему, сервер, порт и дополнительные части URL |
| `validate_host(host)` | Проверяет синтаксис имени сервера или IPv6-адреса |
| `validate_test_file(repository)` | Проверяет наличие, доступность и кодировку файла |

При `argv=None` функции `main` и `parse_config` используют аргументы процесса.
Функции проверки возвращают `None` при успехе и возбуждают `ValueError`
при некорректных данных. `parse_config` превращает ошибку в стандартное
сообщение CLI и завершение с кодом `2`.

## Как объяснить на защите

При запуске `__main__.py` вызывает `main`. Парсер `argparse` получает
две обязательные строковые опции и два логических флага. Из них создается
`Config`, затем проверяются значения с учетом тестового режима.
Если все верно, программа печатает четыре строки. При ошибке парсер
выводит сообщение в stderr и завершает процесс с кодом `2`.

Проверки вынесены из CLI в отдельный модуль: их можно будет использовать
при добавлении получения POM-файлов и обхода графа на следующих этапах.
`frozen=True` запрещает изменять уже созданную конфигурацию.
Стандартная библиотека позволяет запускать проект без установки пакетов.
