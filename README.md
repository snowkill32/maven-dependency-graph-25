# Зависимости Maven: учебная реализация с начала

Практическая работа №2, вариант 25.

Эта ветка содержит повторную учебную реализацию по небольшим шагам.
Готовая версия этапов 1 и 2 сохранена в ветке `main` того же репозитория.

Первый этап завершен: добавлены четыре параметра командной строки,
вывод конфигурации и проверки ошибок. Используется только стандартная
библиотека Python. Загрузка POM и получение зависимостей относятся
ко второму этапу и в этой учебной ветке еще не реализованы.

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки и сборка не нужны.
Из корня проекта:

```shell
python -m src --package junit:junit:4.13.2 --repository https://repo1.maven.org/maven2/
python -m src --help
```

В Windows также можно использовать:

```powershell
.\run.bat --package junit:junit:4.13.2 --repository https://repo1.maven.org/maven2/
.\run.bat --help
```

Успешный запуск печатает:

```text
package=junit:junit:4.13.2
repository=https://repo1.maven.org/maven2/
test_mode=false
ascii_tree=false
```

## Параметры

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--package` | Координаты Maven или имя тестового пакета | Обязательна |
| `--repository` | URL репозитория или путь к тестовому файлу | Обязательна |
| `--test-mode` | Работа с локальным тестовым репозиторием | `false` |
| `--ascii-tree` | Настройка ASCII-дерева, которое появится на этапе 5 | `false` |

Флаги включаются присутствием: `--test-mode`, без `=true`.
Справка и обычный запуск возвращают код `0`. При отсутствии обязательных
опций или неизвестном аргументе `argparse` выводит ошибку в stderr и код `2`.

На первом этапе зависимости не загружаются, выводится только конфигурация.

## Проверка значений

В обычном режиме `--package` должен содержать три непустые части
`groupId:artifactId:version`, без пробелов. В groupId разрешены
буквы, цифры, `_`, дефисы и разделяющие сегменты точки.
В artifactId разрешены буквы, цифры, `_`, точки и дефисы.
Имя артефакта начинается с буквы, цифры или `_`.
Версия начинается с буквы или цифры, далее допускает буквы, цифры,
точки, `_`, `+` и дефисы.

`--repository` должен быть абсолютным HTTP(S) URL с ASCII-именем сервера
или IPv6-адресом. Порт, если указан, должен быть в диапазоне 1-65535.
URL не должен содержать пробелы, логин, пароль, query-параметры или фрагмент.
На этом этапе проверяется только синтаксис URL, доступ к сети не нужен.

С `--test-mode` имя пакета - одна большая латинская буква A-Z,
а репозиторий - существующий доступный для чтения файл UTF-8.
Пример запуска:

```shell
python -m src --package A --repository examples/repository.json --test-mode --ascii-tree
```

```text
package=A
repository=examples/repository.json
test_mode=true
ascii_tree=true
```

Относительный путь к файлу считается от текущего рабочего каталога;
скрипт `run.bat` предварительно переходит в каталог проекта.
Пути с пробелами нужно заключать в кавычки.
Файл читается для проверки доступности и кодировки, его содержимое
пока не интерпретируется как граф. Существование пакета внутри файла
также не проверяется: работа с тестовым графом относится к этапу 3.
`--ascii-tree` пока только сохраняет настройку для этапа 5.

## Демонстрация ошибок

Следующие команды завершаются с кодом `2` и сообщением в stderr.
При ошибке конфигурация не печатается, Python traceback отсутствует.

```shell
python -m src --package demo --repository https://example.org
python -m src --package g:app:1 --repository not-a-url
python -m src --package A --repository examples/repository.json --test-mode=true
python -m src --package g:app:1 --repository https://example.org --ascii-tree=true
python -m src --package A --repository missing.json --test-mode
```

Причины ошибок по порядку: неполные координаты Maven, неверный URL,
переданное значение флагу тестового режима, значение флагу ASCII-дерева
и отсутствующий файл. Чтобы выключить любой флаг, его нужно опустить.
Также обрабатываются пустые значения, отсутствие обязательных опций,
неизвестные или сокращенные опции, каталог вместо файла и неверная кодировка.

## Тесты

```shell
python -m unittest discover -s tests -v
```

18 тестов, включая группы ошибочных значений для каждого параметра
и два запуска настоящего процесса Python. Проверяются stdout, stderr
и коды завершения. Внешняя сеть и сторонние библиотеки не нужны.
Временные файлы создаются отдельно для тестов и удаляются автоматически.
Отказ доступа к файлу моделируется через `unittest.mock`,
чтобы проверка одинаково работала на разных операционных системах.

## Файлы и функции

- `src/__main__.py` запускает приложение через `python -m src`.
- `src/cli.py`: `build_parser()` описывает опции, `parse_config(argv)`
  получает значения, `format_config(config)` формирует вывод.
- `main(argv)` запускает чтение и вывод; при `argv=None` читаются
  аргументы текущего процесса.
- `src/config.py`: неизменяемый `Config` хранит четыре настройки.
- `validate_config(config)` выбирает правила по режиму.
- `validate_package(package, test_mode)` проверяет координаты или букву A-Z.
- `validate_url(repository)` проверяет URL и добавляет имя опции к ошибке.
- `validate_url_parts(url)` и `validate_host(host)` проверяют компоненты URL.
- `validate_test_file(repository)` проверяет наличие, чтение и кодировку файла.
- Функции проверки возвращают `None` при успехе и возбуждают `ValueError`
  при ошибке. `parse_config` превращает его в сообщение CLI с кодом `2`.
- `run.bat` запускает программу из каталога проекта и сохраняет код выхода.
- `tests/test_cli.py` проверяет опции и значения, `tests/test_launch.py` -
  точку входа и коды завершения отдельного процесса.
- `examples/repository.json` содержит небольшой файл для тестового режима.
