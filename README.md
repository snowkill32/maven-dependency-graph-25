# Зависимости Maven - практическая работа №2, вариант 25

Реализованы этапы 1 и 2 по заданию «УНБО-04-25», стр. 80.
Программа получает настройки из командной строки, загружает POM пакета
из указанного HTTP(S)-репозитория и выводит его прямые зависимости.
Используется Python и только его стандартная библиотека.
Maven, другие менеджеры пакетов и библиотеки для получения зависимостей
не вызываются.

Репозиторий: <https://github.com/snowkill32/maven-dependency-graph-25>.

## Выполненные этапы

| Этап | Что сделано |
| --- | --- |
| 1. Конфигурация | Четыре опции CLI, проверка параметров, вывод ключ-значение, обработка ошибок |
| 2. Сбор данных | Загрузка POM по Maven layout, получение и вывод прямых зависимостей |

Третий этап не реализован. Транзитивные зависимости не загружаются,
граф не строится, BFS и DFS не используются. ASCII-дерево относится к этапу 5.

Первоначальная версия этапа 1 доступна в коммите
[`5e31c44`](https://github.com/snowkill32/maven-dependency-graph-25/tree/5e31c44).
В текущем обычном режиме вместо настроек выводятся зависимости,
как требуется на этапе 2. Тестовый режим пока сохраняет поведение этапа 1.

## Требования и запуск

Нужен Python 3.10 или новее. Установка дополнительных библиотек,
сборка проекта и установка Java/Maven не требуются.
Для обращения к внешнему репозиторию нужен доступ к сети.
Команды выполняются из корня проекта.

```shell
python --version
python -m src --help
python -m src --package junit:junit:4.13.2 --repository https://repo1.maven.org/maven2/
```

Результат:

```text
Прямые зависимости junit:junit:4.13.2:
- org.hamcrest:hamcrest-core:1.3 [scope=compile, type=jar, optional=false]
- org.hamcrest:hamcrest-library:1.3 [scope=test, type=jar, optional=false]
```

В Windows можно запустить через скрипт:

```powershell
.\run.bat --package junit:junit:4.13.2 --repository https://repo1.maven.org/maven2/
```

В Linux/macOS:

```shell
sh run.sh --package junit:junit:4.13.2 --repository https://repo1.maven.org/maven2/
```

Скрипты переходят в каталог проекта и сохраняют код завершения программы.
При прямом запуске `python -m src` относительные пути считаются
от текущего рабочего каталога. Пути с пробелами заключаются в кавычки.

## Настройки командной строки

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--package` | Координаты `groupId:artifactId:version`, например `junit:junit:4.13.2` | Обязательна |
| `--repository` | Базовый HTTP(S) URL, с `--test-mode` - путь к UTF-8 файлу | Обязательна |
| `--test-mode` | Проверка локальной конфигурации первого этапа | `false` |
| `--ascii-tree` | Настройка будущего ASCII-вывода; пока вывод остается плоским | `false` |
| `-h`, `--help` | Показать справку и завершить программу | - |

В координатах пакета обязательны все три части, пробелы запрещены.
В `groupId` допускаются буквы, цифры, `_`, дефисы и разделяющие сегменты
точки. Дефис нужен, например, для группы `commons-io`.
`artifactId` допускает буквы, цифры, `_`, точки и дефисы.
Версия начинается с буквы или цифры и может содержать `.`, `_`, `+`, `-`.
Для загрузки следует указывать конкретную опубликованную версию.

URL должен содержать схему `http` или `https` и имя сервера.
Порт, если задан, должен быть в диапазоне 1-65535.
Пробелы, логин и пароль, query-параметры и фрагмент в URL не допускаются.
Путь внутри URL сохраняется, завершающий `/` необязателен.
Программа использует именно указанный репозиторий, без скрытого
переключения на другой сервер.

Флаги включаются присутствием: `--test-mode`, `--ascii-tree`.
Запись `--test-mode=true` или `--ascii-tree=false` является ошибкой.

## Как получается список зависимостей

1. Точки в groupId заменяются на `/`, затем строится путь к POM.
   Для `org.example:demo:1.0` это `org/example/demo/1.0/demo-1.0.pom`.
2. `urllib.request` получает POM с тайм-аутом 15 секунд на сетевую операцию.
   Размер одного POM ограничен 2 МиБ. Проверка HTTPS-сертификатов включена.
3. `xml.etree.ElementTree` читает XML со стандартным namespace Maven.
4. Из родительских POM наследуются свойства, объявления зависимостей
   и `dependencyManagement`. Дочерние значения имеют приоритет.
5. `${...}` раскрываются по свойствам проекта. Отсутствующие версии
   берутся из `dependencyManagement`, включая импортированные BOM.
6. Выводится список прямых зависимостей с координатами, scope, type,
   classifier при наличии и признаком optional.

Вывод включает `compile`, `provided`, `runtime`, `test`, `system`
и optional-зависимости. Это перечень объявленных прямых зависимостей
с учетом наследования, без фильтрации только по runtime-classpath.
Если зависимостей нет, выводится `Прямых зависимостей нет.`.

`dependencyManagement` задает значения полей, но сам по себе
не добавляет зависимости в результат. Зависимости плагинов
из `build/plugins` также не включаются.
Дополнительные загрузки родительских POM и BOM нужны для разбора метаданных;
POM самих найденных зависимостей программа не запрашивает.
Кэш моделей хранится в памяти только до завершения запуска.
В цепочках родителей/BOM проверяются циклы и предел вложенности 32.
Для раскрытия свойств предел вложенности равен 40.

Правила формата сверены с официальными описаниями
[POM](https://maven.apache.org/pom.html),
[Maven layout](https://maven.apache.org/repositories/layout.html)
и [управления зависимостями](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html).

## Примеры второго этапа

Команды, проверенные с Maven Central:

```shell
python -m src --package junit:junit:4.13.2 --repository https://repo1.maven.org/maven2/
python -m src --package org.slf4j:slf4j-api:2.0.13 --repository https://repo1.maven.org/maven2/
python -m src --package com.fasterxml.jackson.core:jackson-databind:2.17.2 --repository https://repo1.maven.org/maven2/
```

При проверке 27.10.2026 получены 2, 1 и 12 прямых зависимостей соответственно.
У SLF4J показана унаследованная `junit:junit:4.13.1` со scope `test`.
У Jackson версии `jackson-core` и `jackson-annotations` раскрываются
из свойств родительской модели.

Без внешней сети можно поднять HTTP-сервер с учебным репозиторием:

```shell
python -m http.server 8000 --bind 127.0.0.1 --directory tests/fixtures
```

В другом терминале из корня проекта:

```shell
python -m src --package g:app:1 --repository http://127.0.0.1:8000/maven2/
```

```text
Прямые зависимости g:app:1:
- g:lib:2.5 [scope=compile, type=jar, optional=false]
- g:managed:3 [scope=runtime, type=jar, optional=false]
- g:test-helper:4 [scope=test, type=jar, optional=true]
```

Файлы в `tests/fixtures` написаны для тестов. В них есть родительский POM,
BOM, пакет без зависимостей `g:empty:1` и поврежденный POM `g:broken:1`.
Остановить сервер можно сочетанием Ctrl+C.

## Тестовый режим первого этапа

```shell
python -m src --package A --repository examples/repository.json --test-mode --ascii-tree
```

```text
package=A
repository=examples/repository.json
test_mode=true
ascii_tree=true
```

Этот режим проверяет параметры и доступность UTF-8 файла, затем выводит
конфигурацию. Имя пакета - одна большая латинская буква A-Z.
Содержимое JSON пока не интерпретируется: загрузка тестового графа
и его обход относятся к третьему этапу и в эту версию не входят.

## Ошибки и коды завершения

| Код | Значение |
| --- | --- |
| `0` | Успешное выполнение или показ справки |
| `1` | Ошибка HTTP, соединения, XML, свойств или данных POM |
| `2` | Ошибка опций или значений конфигурации |

При ошибке результат не выводится частично. Сообщение идет в stderr,
без Python traceback. Для ошибки конфигурации дополнительно показывается usage.

Примеры ошибок каждого параметра:

```shell
python -m src --package demo --repository https://repo1.maven.org/maven2/
python -m src --package g:app:1 --repository not-a-url
python -m src --package A --repository examples/repository.json --test-mode=true
python -m src --package g:app:1 --repository https://repo1.maven.org/maven2/ --ascii-tree=true
python -m src --package A --repository missing.json --test-mode
```

Сообщения указывают на неверные координаты, неверный URL,
переданное значение флагу `--test-mode`, значение флагу `--ascii-tree`
и отсутствие тестового файла. Все пять команд завершаются с кодом `2`.
Также обрабатываются пропущенные опции и значения, пустые строки,
неизвестные опции, неверный порт, кодировка и ошибка доступа к файлу.

Для HTTP 404 сообщается, какой POM не найден. Для других HTTP-ошибок
показывается код сервера. Ошибки сертификата и тайм-аут не скрываются;
для проблемного сервера можно явно выбрать другой URL репозитория.
Неизвестные свойства, циклы свойств, неверные scope/optional
и отсутствующие версии дают явную ошибку.

## Проверка и тесты

```shell
python -m unittest discover -s tests -v
```

59 тестов: параметры CLI, XML с namespace и без него, свойства,
наследование, управление версиями, BOM, ошибки загрузки и вывод результата.
Проверяются коды завершения настоящего процесса Python.
Интеграционные тесты поднимают HTTP-сервер на свободном локальном порту
и проверяют, что загружаются только исходный POM, родитель и BOM.
Внешняя сеть для тестов не нужна. Временные серверы и файлы очищаются.
HTTP-ошибки, тайм-ауты и отказ доступа дополнительно моделируются mock-объектами.

## Структура проекта и функции

```text
src/
  __main__.py      точка входа
  cli.py           опции, сообщения и вывод
  config.py        конфигурация и проверки параметров
  pom.py           чтение XML и модели данных
  properties.py    подстановка свойств и слияние полей
  resolver.py      наследование и импорт BOM
  repository.py    адреса Maven layout и HTTP
tests/
  test_*.py        автоматические проверки
  fixtures/       учебный HTTP-репозиторий
examples/
  repository.json конфигурационный пример первого этапа
run.bat           запуск в Windows
run.sh            запуск в Linux/macOS
```

| Модуль | Функции и классы |
| --- | --- |
| `config` | `Config` хранит настройки; `validate_config` выбирает проверки режима |
| `config` | `validate_package`, `validate_url`, `validate_test_file` проверяют входные данные |
| `config` | `validate_host`, `_validate_url_parts` проверяют компоненты адреса |
| `cli` | `build_parser`, `parse_config` описывают и получают опции; ошибки дают код 2 |
| `cli` | `format_config` выводит настройки; `format_dependencies` формирует список |
| `cli` | `main` выбирает режим; код 0 при успехе, 1 при ошибке загрузки или POM |
| `pom` | `Pom` хранит модель; `Dependency` хранит семь полей зависимости |
| `pom` | `Dependency.coordinates` дает координаты, `key` учитывает type/classifier |
| `pom` | `parse_pom` читает XML; `element_text`, `read_coordinates`, `read_dependencies` читают разделы |
| `properties` | `expand` раскрывает свойства; `property_context` добавляет алиасы координат |
| `properties` | `expand_dependency` раскрывает поля; `merge_dependency` объединяет объявления |
| `properties` | `complete_dependency` применяет управление и значения по умолчанию, проверяет результат |
| `resolver` | `coordinate_string` получает координаты; `inherit_pom` объединяет модели |
| `resolver` | `merge_declarations` объединяет зависимости по group/artifact/type/classifier |
| `resolver` | `PomResolver` принимает загрузчик, хранит кэш и цепочку обработки |
| `resolver` | `_model` читает модель с родителями; `_import_management` подставляет объявления BOM |
| `resolver` | `direct_dependencies` получает итоговый список прямых зависимостей |
| `repository` | `pom_url` строит адрес; `download_pom` возвращает XML-байты |
| `repository` | `get_direct_dependencies` соединяет загрузчик и разбор модели |

`main(argv)` и `parse_config(argv)` при `argv=None` используют аргументы процесса.
Функции проверки и чтения при некорректных данных возбуждают `ValueError`.
`PomResolver(load)` получает функцию вида `load(coordinates) -> bytes`,
что позволяет проверять разбор без сети. `Config` и `Dependency` неизменяемы.

## Границы реализации

Поддерживается статическая модель POM 4.0.0: зависимости верхнего уровня,
наследование, properties, dependencyManagement и BOM.
Активация profiles, settings.xml, Java system properties и свойства окружения
не интерпретируются. Зависимости внутри profiles и плагинов не выводятся.
Если для нужного поля требуется неизвестное свойство, программа сообщает об ошибке.
Дополнительные repositories из POM не подключаются: используется URL из CLI.
Выбор версии из диапазона и timestamped SNAPSHOT по maven-metadata.xml
не реализован; диапазон в объявлении прямой зависимости выводится как в POM.
Это не замена полной сборочной модели Maven.

## Что объяснить на защите

Аргументы разбирает `argparse`. По трем частям координат строится URL POM.
XML загружается через `urllib`, затем читается через `ElementTree`.
Свойства и управление версиями нужны потому, что версия зависимости
может находиться в родителе или BOM, а не в самом объявлении.
После подстановок печатается плоский список прямых зависимостей.
Они не обходятся рекурсивно: BFS с рекурсией нужен только на третьем этапе.

Для сдачи в СДО нужны URL открытого репозитория и PDF-версия этого README.
PDF можно получить через печать страницы README в браузере (Ctrl+P).
Сгенерированные PDF, бинарные файлы и кэш в Git не включаются.
